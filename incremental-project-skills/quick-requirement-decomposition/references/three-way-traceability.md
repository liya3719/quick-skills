# 三向追溯矩阵（拆解 ↔ 技术方案 ↔ 测试用例）

> **何时加载**：Step 4 追溯矩阵完成后；非首版拆解**必填**互验小节。技术方案、用例 skill 升版时须与本矩阵**REQ 编号一致**。

## 目标

防止三文档漂移：每条 REQ 在拆解、方案、用例间**可双向 Ctrl+F**，变更后仅增量行仍须互验。

## 主矩阵（写入拆解文末或 `docs/prd/{需求名}-trace-matrix-v{x.y}.md`）

| REQ | 需求摘要 | 拆解锚点（§/REQ 块） | 技术方案锚点 | TC 编号（功能/异常/边界） | 变更类型* | 状态 |
|-----|----------|----------------------|--------------|---------------------------|-----------|------|
| REQ-001 | … | §5 REQ-001 | `tech-solution-v1.0.md` §4.2 | TC-F-01, TC-E-01 | 无变化 | OK |
| REQ-003 | … | §5 REQ-003 | `tech-solution-v1.1.md` §5.1 | TC-F-12（v1.1 新增） | 修改 | OK |

\* **变更类型**（相对上一版三件套）：`新增` / `修改` / `废弃` / `无变化`。首版可省略列。

**状态**：`OK` / `BLOCKED`（引用 OPEN-xxx）/ `待方案` / `待用例` / `N/A`（须写理由）

## 互验规则 ⛔（交付拆解前）

逐项自问，任一项为否则**回到对应 Step**：

1. 本版 §9.2 中每个**新增/修改** REQ 是否都在矩阵有一行？
2. 「拆解锚点」是否能在本文件找到？
3. 若技术方案已存在：「技术方案锚点」列是否能在对应方案文件找到？
4. 若用例已存在：「TC 编号」是否能在 `docs/testcase/` 对应用例文件找到？
5. 是否存在**仅有 TC 无 REQ**、**仅有方案无 REQ** 的 orphan？
6. 三文档 REQ 编号是否**统一以本拆解为准**？

## 增量升版时的矩阵策略

- **无变化 REQ**：矩阵行可写「同 `{上一版拆解}` / `{上一版方案}` / `{基线 TC}`」，状态 `OK`。
- **修改/新增 REQ**：必须更新方案锚点与 TC 列；旧 TC 废弃须在矩阵标 `deprecated` + 替代 TC。
- 拆解先交付 → 方案升版 → **研发确认方案** → 用例升版；每步更新矩阵副本或递增 `{需求名}-trace-matrix-v{x.y}.md`。

## 与下游 skill 的分工

| Skill | 矩阵职责 |
|-------|----------|
| `quick-tech-solution` | 附录 A 对齐 REQ；升版附录 D 对齐拆解 §9.2；确认后触发用例 |
| `quick-requirement-testcase-trace` | 用例升版后回填 TC 列；变更对照区对齐 §9.2 |

## 禁止

- 用「整体功能」「相关需求」代替 REQ 编号
- 宣称互验通过但矩阵缺行或锚点不可检索
- 拆解已升版、方案/用例仍引用旧拆解版本而不标注
