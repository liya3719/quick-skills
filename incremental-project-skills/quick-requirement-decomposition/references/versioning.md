# 版本与变更追溯（拆解文档 ↔ 原始 PRD ↔ 代码）

**语言**：正文默认中文；版本号、`REQ-xxx`、`PRD-` 等标记保持英文或既定格式。

## 目标

- **原始 PRD 变更后**：不在历史拆解正文上「直接覆盖改写」；保留可追溯的原始记录与每一版拆解快照。
- **研发可见**：哪一版拆解文档用于 Coding、相对上一版哪些 **REQ 模块** 变了、**变更内容** 是什么。
- **代码对齐**：仓库内能指向「实现所依据的拆解版本」（分支/标签/工单/提交说明均可，但必须可解析）。

## 核心规则（IRON）

1. **原始 PRD 只追加、不覆盖**：每次产品定稿或变更定稿，在仓库中保留一份**不可变快照**（见下文命名）。
2. **拆解文档按版本新增文件**：新版本拆解应**新建文件**（或新目录条目），而不是在旧版 `…-v0.1.md` 里改写成 v0.2 内容。
3. **变更必须显式记录**：在新版拆解中增加「版本与变更记录」章节（见 `output-template.md`），并维护根目录或专题下的 **`CHANGELOG` 索引**（可选用 `docs/prd/CHANGELOG.md` 单文件聚合多需求线）。
4. **REQ 编号策略**：
   - **修改**某条能力：保留 `REQ-xxx` 编号，在变更表中说明「修改前后差异」；正文中以本版为准写全量描述。
   - **新增**能力：使用新编号 `REQ-0xx`（接续最大号）。
   - **废弃**能力：将 `REQ-xxx` 标记为 `deprecated`，写明被哪条替代或从哪版起不再实现，**勿静默删除**以免研发误读旧分支。

## 推荐仓库布局（可按项目裁剪）

```
docs/
  prd/
    README.md                 # 本目录约定（可选）
    CHANGELOG.md              # 聚合变更索引（可选，多需求线时很有用）
    _snapshots/               # 原始 PRD 不可变快照（推荐）
      需求名称-prd-v1-20260401.md
      需求名称-prd-v2-20260420.md
    需求名称-v0.1.md   # 拆解终稿 v0.1（对应某次 PRD 快照）
    需求名称-v0.2.md   # 拆解终稿 v0.2
    CURRENT                   # 可选：纯文本，仅一行，写明当前实施所用拆解文件名
```

- **`_snapshots/`**：存放从飞书/钉钉/语雀导出的 PRD 副本或人工拷贝；文件名含 **业务键 + PRD 版本 + 日期**。
- **拆解文件名**：`{需求简称}-v{主}.{次}.md`。破坏性变更可升主版本（如 v1.0 → v2.0），增量变更升次版本（v0.1 → v0.2）。

## 与代码的绑定方式（任选其一，团队统一即可）

在拆解文档头或聚合 `CHANGELOG` 中写明 **实现基线**，至少包含：

| 字段 | 说明 |
|------|------|
| 拆解文档版本 | 如 `v0.2` 或 `DS-20260420-01` |
| Git | 分支名、或 tag（如 `req-需求-v0.2`）、或合并提交的 SHA |
| 工单 | Jira/禅道 链接（若有） |

研发规范建议：**合并请求描述 / 发布说明**中写一行：`Implements decomposition: 需求名称-v0.2.md`。

## 变更记录最小字段

对每一次「拆解新版本」填写：

- **上游**：引用的 PRD 快照文件名与版本说明；**非首版**另填基线快照路径与 **PRD diff 摘要**（见 `prd-diff-incremental.md`）。
- **相对上一版拆解**：新增/修改/废弃的 REQ 列表；影响模块一句话摘要。
- **OPEN**：关闭或新增的待澄清编号。
- **三向矩阵**：§11 或独立 trace 文件已更新；与 `three-way-traceability.md` 互验通过。

| 顺序 | 产物 | 规则 |
|------|------|------|
