# 输出模板

**语言**：正文默认使用中文；结构化标记（REQ-xxx、OPEN-xxx、BLOCKED、N/A）保持不变。

每次拆解均采用下列结构。替换占位内容；若无对应待澄清项，勿单独留下 `TBD`。

## 1. 文档头

| 字段 | 内容 |
|------|------|
| 标题 | |
| 来源 | PRD 链接、工单或粘贴说明 |
| 拆解人 | |
| 日期 | |
| 拆解文档版本 | 语义化版本，如 `v0.1`、`v1.0`；全文文件命名建议与之一致（`{需求名}-v0.1.md`） |
| 上游 PRD 快照 | 仓库内不可变快照路径，如 `docs/prd/_snapshots/{需求}-prd-v2-20260420.md`；**禁止**仅写「见飞书/钉钉文档等」而无固定副本 |
| 继承自 | 上一版拆解文件路径；首版写 `none` |
| 版本 | 可与「拆解文档版本」同列展示；或用于 PRD 侧版本号 |

**说明**：原始 PRD 每次定稿变更应新增快照文件，不覆盖旧快照。拆解侧随 PRD 变更**新建**本文件的新版本，不在旧版拆解文件上改写正文冒充同一版。细则见同目录 `versioning.md`。

- **假设**：仅列出原文已说或可合理推出的；每条标注「已确认」或「待确认」。

## 9. 版本与变更记录

**首版**：可仅写一行：`本版为首次拆解，无上一版差异。`

**非首版必填**：说明相对「继承自」那一版发生了什么变化，便于研发做差异开发与回归范围评估。

### 9.1 PRD 与拆解版本对应

| 项目 | 内容 |
|------|------|
| 本拆解版本 | 如 v0.2 |
| 引用的 PRD 快照 | 文件路径 + 一句话说明（可选） |
| 上一版拆解文档 | 文件路径 |
| 变更摘要（给研发） | 一段话：业务上为何升级版本 |

### 9.2 REQ 级变更清单

| REQ-ID | 变更类型（新增 / 修改 / 废弃） | 变更说明（旧→新或废弃原因） | 备注（影响范围、兼容） |
|--------|-------------------------------|-----------------------------|------------------------|
| REQ-xxx | 修改 | 变更说明 | 影响 REQ-xxx |
| REQ-xxx | 新增 | 新增说明 | 无 |

- **修改**：在正文该 REQ 块中写**完整现行描述**（不要只写增量一句）。
- **废弃**：仍保留一行，类型填 `废弃`，并写明从哪一版起不实现或被子 REQ 替代。

### 9.3 OPEN 编号变更（若有）

| 编号 | 变更（新增 / 关闭 / 合并） | 说明 |
|------|---------------------------|------|
| OPEN-xxx | 关闭 | 说明 |

## 10. 实现基线（研发 Coding 对齐）

用于回答：**当前代码是以哪一版拆解文档为准实现的**。与第 1 节配合使用。

| 字段 | 内容 |
|------|------|
| 作为实现依据的拆解文档 | 本文件路径 + 版本号 |
| Git | 分支名、或 tag、或约定合并后的 commit SHA（上线后补全亦可） |
| 工单 / 发布 | 可选 |
| 说明 | 例如：「main 在 2026-05-11 合并后对应本拆解 v0.2」 |

**团队规范建议**：合并请求标题或描述中带：`Decomp: {文件名}-v{x.y}`，便于搜索。
