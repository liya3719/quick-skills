# 架构对齐报告

## 何时加载

步骤 8 实现结束后、**编译验证前** **必读**；须落盘后方可进入步骤 9 门禁。

## 落盘路径

默认：`docs/ai/codegen/{需求名}-架构对齐报告-v{x.y}.md`

## 必覆盖章节

| 章节 | 内容 |
|------|------|
| **1. 元数据** | 拆解(`docs/prd/`)/方案(`docs/design/`)/设计数据(`design/`)/项目规则/执行计划版本；各物料研发确认记录；git 基线与 HEAD |
| **2. 文件清单** | 变更文件；REQ/block 映射 |
| **3. 分块对齐** | 每 block：计划 vs 实际文件/组件；状态 pass / missing / blocked |
| **4. 接口字段** | 方案字段 vs types/api 实现；差异表 |
| **5. 路由与平台** | Web/Native/ZRN 注册；深链；与方案一致否 |
| **6. ZRN UI 与样式** | token/metadata 引用；硬编码清单（应为空或 OPEN） |
| **7. 埋点与日志** | 事件名/参数 vs 方案；缺口 |
| **8. 偏差** | 相对方案/REQ 的未批准差异 |
| **9. 待验证项** | 需人工/QA/编译后验证的条目 |

## 关键项判定

**关键项**（须全部 `pass` 才可进入编译验证）：

- 每个本迭代 **P0 REQ** 至少一个 block 为 `pass`
- 无未解释的 **接口字段 missing**
- 无未批准的 **路由/平台 missing**
- UI 相关 REQ：**设计 metadata 已用**或已标 `UI-N/A`（有 OPEN）
- **blocked** block 未静默实现

非关键 `missing` 可记入待验证项，但须在报告中显式列出。

## 回流规则 ⛔

| 结果 | 动作 |
|------|------|
| 关键项 **pass** | 进入步骤 9 编译验证 |
| 关键项 **missing** | 回流补全（更新代码 + 修订报告）；**最多 5 轮** |
| 5 轮后仍 missing | 整单标 **`blocked`**；禁止宣称可合入 |
| 存在 **blocked** block 被实现 | 视为门禁失败，回滚或补文档 |

每轮回流须在报告末尾追加「回流记录」：轮次、missing 项、补全动作、结果。

## 禁止

- 仅口头「对齐了」无落盘报告即跑编译
- missing 不回流直接 merge
- 超过 5 轮仍 missing 却标 pass
