# 偏差分级与容差

## 何时加载

步骤 3。

## 严重度

| 级别 | 定义 | 回流 |
|------|------|------|
| **P0** | 破坏设计契约：结构错、品牌主色错、必现状态缺失、错图/缺图 | 必须 codegen 修复 |
| **P1** | 可感知还原问题：超容差间距字号、断点错误、次要状态 | 应回流修复 |
| **P2** | 轻微差异、待补 token、仅设计稿内部不一致 | 可 OPEN，不阻塞 pass |

## 默认容差（无项目约定时）

| 类型 | 容差 | 超出 |
|------|------|------|
| 间距 px | ±2px | P1 |
| 字号 px | ±1px | P1 |
| 颜色 | token 不一致或 ΔE 明显（非同一 token） | P0（主色）/ P1（次要） |
| 圆角/阴影 | token 名不一致 | P1 |

项目 `AGENTS.md` 有约定时**以项目为准**。

## 不可自动判 pass

- metadata 与 token JSON 冲突 → OPEN-设计
- 方案未定义的状态却 metadata 有 → decision OPEN
- 用户未确认的 UI-N/A block

## 禁止

- 全部标 P2 规避回流
- 无数值的「感觉不对」标 P0
