# 逻辑校验

> 在 Step 5 中加载。验证**业务语义**是否正确，而非仅语法/空值。先对齐 Step 1 数据流中的**状态变更**与**权限决策点**。

## 对齐预期（BLOCKING 子步）

在扫代码前，用 1～3 句写清（无 PRD 则从代码/注释/测试**推断**并标「假设」）：

- 本 scope **应完成**什么业务结果？
- **谁**在什么条件下**允许/禁止**操作？
- 是否存在**状态机**（订单/审批/库存/会话）？合法迁移有哪些？

缺业务上下文时：**不**判「逻辑错误」，只列「待确认规则」。

## 校验维度

### 1. 分支与条件

- 问：`if/else` 是否**漏**边界（等于、空集、已取消、已过期）？
- 问：多个 `if` 是否**互斥**完备，还是可能**双执行**或**都不执行**？
- 问：早返回是否导致**后续必要步骤**被跳过（如未记账已发货）？

### 2. 状态与不变量

- 问：状态迁移是否**单向**或**可逆**符合业务？非法迁移是否被拦截？
- 问：跨字段不变量是否成立（如 `paidAmount <= total`、`stock >= 0`）？
- 问：**部分失败**时状态是否一致（半成功、半写入）？

### 3. 权限与归属逻辑

- 问：鉴权条件是否与**资源 owner/租户**绑定，而非仅「已登录」？
- 问：管理员/系统/internal 接口是否与用户接口**共用**同一套校验？
- 问：批量操作是否**逐条**校验归属，还是只校验第一条？

### 4. 幂等与重复

- 问：支付/发券/扣库存/写订单是否**幂等**（requestId/唯一键/去重表）？
- 问：重试、双点、消息**至少一次**投递会否重复副作用？
- 问：前端防重复提交，**后端**是否仍防？

### 5. 时序与金额

- 问：优惠/价格/费率在**哪一刻**锁定？后续变更会否影响已下单？
- 问：时间窗口（活动开始/结束、冷却）用**服务器时间**还是客户端时间？
- 问：浮点/分/元混用是否导致**舍入**或比较错误？

### 6. 补偿与回滚

- 问：失败路径是否**撤销**已执行的副作用（库存、券、积分）？
- 问：`try/catch` 或事务 rollback 是否覆盖**所有**已写资源？
- 问：异步步骤失败是否有**对账/补偿**任务，还是静默丢？

### 7. 与测试/注释一致性

- 问：单元/集成测试断言的行为是否与实现**一致**？失败测试是否被 skip？
- 问：注释/接口文档描述的规则是否在代码中**兑现**？

## 与「代码质量-边界」的边界

| 代码质量 | 逻辑校验 |
|----------|----------|
| null/越界/类型 | **规则**是否写对 |
| 异常是否处理 | **业务失败**是否按产品定义处理 |
| 资源泄漏 | **钱/库存/权限**是否算对 |

## 严重度

| 级别 | 示例 |
|------|------|
| P0 | 可重复扣款、越权改他人订单、库存可负且无拦截 |
| P1 | 错误分支导致错误计费/错误状态，需特定操作序列 |
| P2 | 极端时序下偶发不一致，或有补偿可对账 |
| P3 | 与文档/注释不一致，主路径正确 |

## 输出要求

每条逻辑问题含：

- **预期行为** vs **实际行为**（各一句）
- **复现条件**（角色、前置状态、操作序列）
- **位置**（决策点 `path:line` 或函数名）

无足够业务依据 → 「待确认规则」，**不**标 P0。
