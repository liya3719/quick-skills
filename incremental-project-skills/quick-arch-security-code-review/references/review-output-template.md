# 输出结构模板

> 交付时对齐此结构，便于与 CI/PR 对照。

## 1. 摘要

- 审查范围（文件/PR/提交 SHA）
- 风险等级总览：P0 数 / P1 数 / …
- 一句话结论

## 2. 分维度发现（按严重度降序）

**建议子节顺序**（有发现时）：漏洞扫描 → 逻辑校验 → 安全 → 架构 → 质量 → 性能 → 死代码。

每项包含：

| 字段 | 说明 |
|------|------|
| ID | 如 R-001 |
| 严重度 | P0（可立即被利用/数据面）/ P1 / P2 / P3 |
| 类别 | 架构 / 安全-注入 / 安全-鉴权 / 安全-其他 / **漏洞扫描** / **逻辑校验** / 质量-错误 / 质量-边界 / 性能 / 死代码-疑似 |
| 位置 | `path:line` 或符号名 |
| 问题 | 一句话 + 相关前提（逻辑类加**预期 vs 实际**；漏洞类加**入口→sink**） |
| 建议 | 可执行的一条（非泛泛「重构」） |

## 3. 死代码清单（仅疑似）

- 表格式：`位置 | 判断依据 | 是否已标注 [DEAD-CODE-CANDIDATE]`
- 声明：**删除须研发确认**。

## 4. 需确认问题（无证据不下结论）

- 列出需运行时/业务规则才能判断的项，避免臆断。

## 5. 可选：修复优先级

- 建议的修复顺序与依赖（不自动改代码，除非用户明确要求）。
