> 初版或全量重写时按本节建文档。需求变更导致的增量见 `change-versioning.md`。

| 字段 | 说明 |
|------|------|
| 文档标题 | 产品/模块名 + 测试用例 |
| 文档版本 | 如 v1.0，与本次覆盖的需求基线一致 |

| 对应拆解需求 | 文件路径或链接 + 版本/日期 |

| 子方案/附录 F 范围（可选） | 本用例集涉及的 `{功能描述}-版本.md` 列表，或写「不区分子方案 / 全量单方案」 |

## 追溯说明（必填）

用 2～4 句说明：本文件如何用 REQ 编号与拆解稿对齐；若某条用例暂时无法绑定 REQ，须标 `BLOCKED` 并引用 OPEN-xxx（与拆解 skill 一致）。已填「对应技术方案/子方案」时，可一句交代与总方案、附录 F 的用途（**辅助回归分域，验收仍以 REQ 为准**）。

## 三层用例生成约定

相对 PRD/拆解生成用例时，**按层输出**，且均须绑定 REQ（与 SKILL IRON LAW 一致）。

### 1. 功能层（正常）

- **粒度**：以 REQ 或拆解中的**核心业务流程**为锚；每个锚点产出 **2～3 条**功能 TC（不同正常路径：例如角色、入口、合法数据集、主成功路径变体）。
- **步骤**：覆盖从触发到结束的**完整主路径**；避免把多条互斥正常流塞进同一条 TC 的「步骤 1/2/3」混写（应拆成多条功能 TC）。
- **优先级**：每条功能 TC 必填（如 P0/P1/P2 或与团队枚举一致）。
- **关联功能用例**：功能层填 **「—」**。

### 2. 异常层（由功能推导）

- **来源**：逐条对照功能 TC，写清「由 TC-xxx 派生」。
- **典型分支**（按需取用，不必机械全写）：参数缺失；类型/格式错误；权限不足；资源不存在；业务规则冲突；**当前状态不允许**该操作；依赖服务失败（若属需求范围）等。
- **预期**：与需求/接口约定的错误码、提示、回滚或幂等语义一致；禁止笼统「报错即可」。

### 3. 边界层

- **输入域**：空值、最小/最大合法、越界、特殊字符、**超长**字符串或列表长度等。
- **时序与并发**：重复提交、并发操作、超时（若需求或 NFR 有约定）。
- **跨模块**：与上下游模块联动的**特殊或极端**情况（仅当拆解或方案已点名接口/契约时写可执行步骤，否则在矩阵标「待方案 OPEN-xxx」）。

**层级与「类型」列**：`用例层级` 取固定枚举 **功能 | 异常 | 边界**；若保留「类型」列，须与之兼容（例如类型写「接口异常」且层级为「异常」），禁止矛盾。

## 用例表（主表）

建议列：

| TC 编号 | 标题 | 追溯 REQ | 用例层级 | 关联功能用例 | 优先级 | 类型 | 前置条件 | 步骤 | 预期结果 | 数据/备注 |
|---------|------|----------|----------|--------------|--------|------|----------|------|----------|-----------|

- **用例层级**：必填，**功能** / **异常** / **边界**。
- **关联功能用例**：异常与边界填**派生所自**的功能 TC 编号；功能层填 **—**。
- **优先级**：功能层建议必填；异常/边界可按团队规范选填或与派生功能 TC 一致。

在**上述基础列**上可**追加**（有总方案+子方案或子任务表时；**不替代**「追溯 REQ」）：

- **关联子方案**：与总方案**附录 F** 一致的文件名或章节约束；无拆分时不追加本列。
- **关联子任务/任务包**：与开发任务表、方案内任务拆分一致；团队未规范编号时可写「人话描述 + 总方案/子方案 §」或留空。说明见同目录下 `tech-solution-trace.md`。

- **TC 编号**：全文件唯一，建议 `TC-001` 递增或 `模块-TC-001`。
- **追溯 REQ**：至少一个 REQ；多条用例可共指同一条 REQ，但禁止「一条用例零 REQ」作为已验收终稿。
- **类型**（可选细化）：在「用例层级」之下可写子类，如兼容 / 性能 / 安全 / 回归 / 接口异常 / 状态机 等，按团队习惯收敛枚举；**层级以「用例层级」列为准**。

## 需求—用例追溯矩阵（推荐）

| REQ 编号 | REQ 摘要（一行） | 覆盖本 REQ 的 TC 编号列表 | 缺口说明 |
|----------|------------------|---------------------------|----------|

缺口列填 N/A 或「待补」「BLOCKED+原因」。可选在表下增加**一行摘要**：各 REQ 对应功能/异常/边界 TC 条数，便于评审三层覆盖。

有子方案分域时，可增一列 **主要子方案**（`{功能}-vX.Y.md`）便于选择性回归，多对多时写「见主表」。

## 需求—用例—子域（可选矩阵）

**仅当** 存在多子方案/多任务包且需按子域看覆盖时使用：| 子方案或任务包 | 覆盖 REQ | 关联 TC 编号 | 备注 |。不得替代上一节的 **REQ 为主** 的矩阵；可与主矩阵二选一或互补。

## 与拆解稿不一致时的处理

若发现拆解稿缺项或 REQ 与 PRD 冲突：在用例文档「待澄清 / 阻塞」表中列出，引用 OPEN-xxx，不自行编造 REQ 编号冒充已确认需求。
