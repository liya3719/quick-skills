# 三层用例生成规则（功能 / 异常 / 边界）

> 编写或评审用例时与 `testcase-doc-template.md` 同读；不改变 REQ 追溯铁律，只规定**分层产出形态**。

## 1. 分层与主表字段

- **层级（必填列）**：`功能` | `异常` | `边界`（团队可映射为「类型」列，取值仅允许这三类 + 用户确认过的扩展如兼容/性能，扩展须在文档头声明）。
- **派生自（异常/边界建议必填）**：填写**来源功能用例**的 TC 编号；纯跨 REQ 的边界可写「多 TC：TC-F-…」或绑定主 REQ 后在备注说明关联功能 TC。
- **优先级**：功能用例必须标 `P0` / `P1` / `P2`（或团队等价枚举）；异常/边界建议标优先级，与风险一致。

**编号**：全文件唯一；推荐前缀便于筛选：`TC-F-001`（功能）、`TC-E-001`（异常）、`TC-B-001`（边界）。若沿用 `TC-001` 递增，须在「层级」列严格区分。

## 2. 功能用例（第一层）

对**每个 REQ 或每个可独立验收的用户能力**（按拆解粒度择一，在文档头写清口径）：

| 规则 | 说明 |
|------|------|
| 正常场景数量 | **每条功能用例含 2～3 个可区分正常场景**（可写进同一条 TC 的「步骤」分场景，或拆成 2～3 条 TC-F，择一并在文档头说明） |
| 主流程 | 覆盖**核心业务路径的完整链路**（从入口到可验证终态；若 REQ 只描述子环节，则该环节输入输出完整） |
| 优先级 | 主路径、监管/资金/安全相关标 `P0`；次要分支 `P1`；锦上添花 `P2` |
| 与矩阵 | 需求—用例矩阵中，每个 REQ 至少对应 **≥1 条功能层 TC**（除非 BLOCKED） |

## 3. 异常用例（第二层，由功能推导）

**生成方式**：遍历每条功能用例（或每个功能场景），问「若在此步失败会怎样」→ 一条异常 TC 对应一类失败模式。

| 类别 | 触发/数据特征（示例） |
|------|------------------------|
| 输入/契约 | 必填参数缺失；类型错误；格式非法 |
| 鉴权与资源 | 权限不足；资源不存在；过期/撤销的令牌 |
| 业务规则 | 规则冲突；重复业务唯一键；不满足前置业务条件 |
| 状态机 | 当前状态不允许该操作；非法状态迁移 |

**书写要求**：步骤中写清**与功能用例的差异点**（只改哪一项）；预期为**可观测错误**（文案码、HTTP/业务码、无副作用）。**派生自**填对应 `TC-F-xxx`。

缺口：若需求未约定错误码，步骤写「记录实际表现」并在备注标 `待产品确认`。

## 4. 边界用例（第三层）

在功能路径上，对**数据与外部环境**取极值与特殊值（可与异常重叠时，归并到一类并在备注说明「兼异常/边界」）。

| 类别 | 覆盖要点 |
|------|----------|
| 数据形态 | 空值/空集合；最小长度；最大允许；刚超最大（超长）；Unicode/特殊字符/危险字符转义 |
| 时间与重复 | 超时；重试；**重复提交**；幂等键冲突 |
| 并发与联动 | **并发**双写；跨模块顺序颠倒；依赖模块降级/不可用（若范围包含） |

**跨模块**：单独 TC-B 或备注中写清依赖模块与**特殊联动条件**；REQ 绑在「发起方」REQ 或双方各一条并备注关联。

## 5. 文档结构建议

二选一（文档头声明）：

1. **单主表**：增加「层级」「派生自」「优先级」列，用筛选或排序区分三层。
2. **分章**：「功能用例」「异常用例」「边界用例」三章，每章内表格列与主模板一致；章首用一小表列出本章 TC 与 REQ 对应关系。

需求—用例矩阵可增列 **功能/异常/边界 TC 数量**，便于一眼看分层覆盖。

## 7. 用例层级总览

分层规则不变；**可视化**按 `mindmap-per-testcase.md`：**一 REQ 一图**，默认 **`flowchart TB`**（模块 → REQ → 功能/异常/边界 → TC 叶子）；主表每条 TC 恰在所属 REQ 的图中出现一次。

## 8. 自检问题（编写完每层后）

- 每个 REQ：**是否至少 1 条功能 TC**，且该功能 TC 是否含 **2～3 个正常场景**？
- 每条功能 TC：**是否**在异常层有计划的派生（或显式写「本 REQ 错误策略未定义，BLOCKED」）？
- 异常/边界 TC：**是否**填写派生自或等价追溯说明？
- 边界：**空、极值、超长、特殊字符**是否至少命中团队约定的「高风险的 1～2 类字段」？
- 每条 TC：**是否**已在所属 REQ 的 flowchart 中作为叶子出现，且层级分支与主表「用例层级」一致？
