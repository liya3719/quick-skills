# QA 回归影响评估（重构后）

## 何时加载

**Step 8**（`/understand --update` 之后）**必读**。

## 前置 ⛔

1. 已执行 **`/understand --update`**，`meta.json` → `lastAnalyzedAt` 已记录
2. 存在 `knowledge-graph.json`（或标注手工分析并附路径证据）
3. 有变更基线 commit（重构开始时记录，或研发确认的 `<base>..HEAD`）
4. 已读 `{artifactRoot}/技术方案.md` 范围卡片与 `测试用例.md`

**禁止**在 `--update` 之前定稿本评估。

## 步骤

### S1 — 变更清单

```bash
git diff <base>..HEAD --name-only
```

产出触及文件列表（附 base / HEAD）。

### S2 — 图谱锚定

对每个触及文件 Grep `knowledge-graph.json`；记录 node id、summary；无节点则标「图谱未覆盖」并用代码 Read 补锚点。

### S3 — 传播扩展

对变更 node：向上 1–2 跳找调用方/入口，向下 1 跳找副作用（网络、事件、存储等）。

### S4 — 功能点映射

- 优先读 `domain-graph.json` 的 `domains[]`
- 将变更点归入 **功能域 + 功能点**（QA 可读名称，非类名）
- 无 domain 时用 `summary` + 范围卡片入口表命名

### S5 — 与计划对比

| 标记 | 含义 |
|------|------|
| 计划内 | 在已确认边界与 Plan 内 |
| 计划外 | 超出范围卡片 → **默认 R0**，须说明 |

### S6 — 回归分级

| 级别 | QA 动作 |
|------|---------|
| **R0** | 冒烟必测 |
| **R1** | 功能域全量回归 |
| **R2** | 抽测 |
| **R3** | 可跳过（须写依据） |

场景优先引用 `测试用例.md` QA 章 TC-ID；无则 `QA-MANUAL-n` + 可执行步骤。

### S7 — 与研发验证交叉

对读 Step 7 回归摘要：单测已覆盖 →「研发已测」；仍须功能回归 →「QA 仍须测」及原因。

## 落盘

`{artifactRoot}/QA回归影响评估.md` — 含元数据、变更摘要、功能点回归矩阵、波及链路、与测试用例对照、QA 执行建议。

## 禁止

- 只列文件、无功能点
- 无路径/node 证据的功能点
- 「单测全过故无需功能回归」且未填 QA 仍须测
