# 验证与反漂移（Step 7.5）

## 何时加载

Step 7 单测通过后、Step 8 之前**必读**。

## 目标

证明：**改对了**、**与批准方案一致**、**无未记录漂移**。

## 验证清单

### V1 — 文档 ↔ 代码对读

| 对照项 | 检查 |
|--------|------|
| 《重构计划Plan》切片 | git diff 中每处变更能否映射到某切片？有无计划外文件？ |
| 《测试用例》研发视角 | 每个 RD 用例 ID 是否有对应自动化或手工执行记录？ |
| Step 2.5 Issue 表 | 「本次要修」项是否在 diff 中有对应？ |
| 范围卡片入口 | 每个等价入口是否至少一条验证路径？ |

计划外变更 → 更新三文档并**重新征得研发确认**，或回滚。

### V2 — 行为等价

对范围卡片中每个**对外入口**回答：

- 问：新旧路径下，输入 X 时输出/副作用是否一致？
- 问：错误码、默认值、时序承诺是否未变（除非方案已批准差异）？
- 证据：RD 用例 ID + 测试名 / 手工步骤 / 日志片段

说不清「哪条用例 + 哪个入口」→ **不得**进入 Step 8。

### V3 — 差异表（有则必填）

| 项 | 重构前 | 重构后 | 是否批准 | 验证方式 |
|----|--------|--------|----------|----------|
| … | … | … | 是/否 | TC-ID |

无差异写「无」；有未批准差异 → 停手修正。

### V4 — 反漂移摘要

```markdown
## 反漂移核对

- 基线 commit：…
- 终版 HEAD：…
- 计划内变更文件数：…
- 计划外变更：有/无（列出并说明）
- 方案/用例修订次数与原因：…
- 结论：通过 / 不通过
```

## 落盘

写入 **`{artifactRoot}/验证报告.md`**（与三文档同目录），结构：

1. 元数据（模块、version、基线/终版 commit）
2. V1–V4 结论
3. 行为等价入口级结果表
4. 遗留风险与 defer

## 禁止

- 仅「单测全过」就宣称等价，无入口级对照
- 计划外 diff 未更新文档仍出终版报告
- 验证结论只存在于对话、未落盘
