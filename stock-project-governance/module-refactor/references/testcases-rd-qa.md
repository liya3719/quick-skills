# 测试用例：研发视角 + QA 视角

## 分工

| 视角 | 关心 | 不关心 |
|------|------|--------|
| **研发** | 契约、分支、错误语义、Plan 切片、单元/集成自动化 | — |
| **QA** | 用户可感知功能、业务场景、回归优先级、手工/E2E | 类名、内部切片、实现细节 |

同文件：`{artifactRoot}/测试用例.md`，分 **`## 研发视角`** 与 **`## QA 视角`**。

## 研发视角

1. **追溯矩阵**：`| 用例 ID | 覆盖契约/分支 | 对应 Plan 切片 |`
2. **自动化归属**：项目约定的测试目录与框架
3. **用例明细**：前置 / 步骤 / 期望（含异常、边界）
4. **执行命令**（项目测试 runner）

ID 建议 `{缩写}-TC-{序号}`；自动化测试标题须含 ID。

## QA 视角

1. **功能影响摘要**（一句话，QA 可读）
2. **功能点回归矩阵**：

| 功能域 | 功能点 | 变更类型 | R0–R3 | 场景描述 | 关联 RD 用例 |
|--------|--------|----------|-------|----------|--------------|

3. **手工 / E2E 场景**（可执行步骤，无实现细节）
4. **环境与数据**

### QA 禁止

- 「验证 `FooService.bar()`」→ 改为「验证下单后订单状态为已支付」

## 与 QA回归影响评估 的关系

| 文档 | 时机 |
|------|------|
| `测试用例.md` § QA | 重构**前**设计 |
| `QA回归影响评估.md` | 重构**后**实际影响 |

## 模板骨架

```markdown
# {模块名} 测试用例（{version}）

## 研发视角
### 1. 用例追溯矩阵
### 2. 自动化归属
### 3. 用例明细
### 4. 执行命令

## QA 视角
### 1. 功能影响摘要
### 2. 功能点回归矩阵
### 3. 手工 / E2E 场景
### 4. 环境与数据
```
