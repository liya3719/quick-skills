# SOLID · 高内聚低耦合 · 性能

在进入「目标结构设计」前，用下列问题自检；答不上来则回到调用图谱补证据。

## 单一职责 SRP

- 问：这个模块未来会因几种**互不相干**的业务原因而变更？若明显多于一种，拆分候选是什么？
- 问：对外暴露的 API 名称是否表达**一个**稳定意图，而不是「大杂烩门面」？

## 开闭 OCP

- 问：新增一种同类能力时，必须改动的文件数量与层级是否可控？能否通过**扩展点**（策略/插件/配置）而非改核心分支？

## 里氏替换 LSP

- 问：若存在继承/实现关系，子类是否**加强**了前置条件或**削弱**了后置保证？（若是，优先组合优于继承。）

## 接口隔离 ISP

- 问：调用方是否被迫依赖它用不到的方法？接口能否按**调用方角色**切开？

## 依赖倒置 DIP

- 问：高层模块是否直接 import 具体基础设施（HTTP、DB、FS、UI）？能否改为依赖**抽象端口**，由外层装配？

## 高内聚 / 低耦合

- 问：同一文件内的函数是否围绕**同一词汇表**与不变量协作？若出现两套无关词汇表，是否应分模块？
- 问：模块间边是「少量稳定契约」还是「穿透式读写对方内部」？后者必须列为**待消除边**。

## 高性能（模块级可核查项）

- 问：热路径上是否有 **O(n²)** 聚合、重复序列化、无界缓存、在循环内做 I/O？
- 问：异步边界是否清晰？是否存在**隐式阻塞**（同步读盘/同步网络）混在 UI 或高频事件路径？
- 问：数据结构是否匹配访问模式（随机读 vs 顺序读、去重 vs 有序）？

## 输出要求

将「结论」写成**可执行的边界陈述**：谁负责什么、禁止什么依赖、扩展点在哪里；不要泛泛写「注意性能」。
