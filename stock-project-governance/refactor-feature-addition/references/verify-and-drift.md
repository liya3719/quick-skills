# 验证与反漂移（Step 7.5）

## 何时加载

Step 8 单测通过后、交付前**必读**。

## 目标

证明：**实现与确认方案一致**、**三文档无未记录漂移**、**上下游回归已覆盖**。

## 验证清单

### V1 — 四方对读（代码 ↔ 需求拆解 ↔ 技术方案 ↔ 测试用例）

| 对照项 | 检查 |
|--------|------|
| 《需求拆解》REQ | 每个 REQ 在代码 diff 中有对应行为？ |
| 《技术方案》§5 最小改动证据 | git diff 每处变更能否映射？有无计划外文件？ |
| 《实施计划》切片 | 全部切片已完成或 defer 已记录？ |
| 《测试用例》研发视角 | 每个 RD/RG 用例是否有执行记录？ |
| 三向追溯矩阵 | 终版是否仍无 orphan？ |

**不一致 → 先改文档并简述原因**，再更新矩阵与验证报告。

### V2 — 存量契约保持

对 Step 1「不应受影响」路径逐项回答：

- 输入 X 时输出/错误语义是否未变？
- 证据：RG 用例 ID + 测试名 / 手工步骤

### V3 — 新功能行为

对每个 REQ 回答：

- 哪条 RD-TC + 哪个入口证明已交付？
- 错误码、默认值是否与《技术方案》一致？

### V4 — 差异表（有则必填）

| 项 | 方案承诺 | 终版实现 | 是否批准 | 验证方式 | 文档修订 |
|----|----------|----------|----------|----------|----------|
| … | … | … | 是/否 | TC-ID | 已修 §x |

### V5 — 反漂移摘要

```markdown
## 反漂移核对

- 确认基线 commit：…
- 终版 HEAD：…
- 计划内变更文件数：…
- 计划外变更：有/无（列出并说明）
- 文档修订次数与原因：…
- 单测：命令 …，结果 全过/失败
- RG 回归：…
- 结论：通过 / 不通过
```

## 落盘

写入 **`{artifactRoot}/验证报告.md`**，结构：

1. 元数据（模块、version、基线/终版 commit、四文档路径）
2. V1–V5 结论
3. REQ 级验证结果表
4. 遗留风险与 defer

## 图谱更新

有代码变更且 understand-anything 可用时：**`/understand --update`**。

## 禁止

- 仅「单测全过」就宣称交付，无 REQ/RG 级对照
- 计划外 diff 未更新文档仍出验证报告
- 验证结论只存在于对话、未落盘
